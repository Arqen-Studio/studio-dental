### The principle applied to example text

When a doctor left our example text in place, the test is not only whether it is
ours but whether it is true of them. A description of clinical work can be kept
if it is grounded in what they wrote elsewhere, reworded so it is not our
boilerplate. A specific credential or activity claim (a named course, a lecture,
a body they are registered with) is only ever taken from their own answer.
Comparing each record against the blank form catches verbatim copies but not
light rewording, so the profiles first built from pasted text (Yousaf, Aqsa,
Alizeh, Rabia) are worth a second read against their own forms.

### Recording enquiries in a spreadsheet

Every enquiry is emailed to the clinic, but email can be deleted or lost. The
spreadsheet keeps a durable record alongside it. It is optional: if
ENQUIRY_SHEET_URL is not set, email is the only record. The site only ever holds
a URL, never a key, and the sheet stays in the clinic's own Google account.

The sheet, "Studio Dental website enquiries", in the tech@arqen.studio Drive:

    https://docs.google.com/spreadsheets/d/1eRWTVtP7EVI-IXK7dIYizfEUs7uvYsedMk1bbnfYoAs/edit

The spreadsheet is written first, then the email is sent, so an enquiry is
recorded even if the mail provider is down. If the spreadsheet is unreachable the
failure is swallowed and the email still sends, since a broken sheet must never
stop a patient reaching the clinic. The consequence is that a sheet which quietly
stops working will not announce itself, so glance at it now and then.

**Apps Script behind the sheet** (Extensions, then Apps Script, in the sheet
itself, not a standalone project):

```javascript
var HEADINGS = ['Received', 'Name', 'Phone', 'Email', 'Clinic',
                'Treatment', 'Preferred date', 'Message'];

function doPost(e) {
  var lock = LockService.getScriptLock();
  lock.waitLock(20000);
  try {
    var ss = SpreadsheetApp.getActiveSpreadsheet();
    var sheet = ss.getSheetByName('Enquiries') || ss.getSheets()[0];
    if (sheet.getLastRow() === 0) sheet.appendRow(HEADINGS);

    var d = JSON.parse(e.postData.contents);
    sheet.appendRow([
      d.receivedAt ? new Date(d.receivedAt) : new Date(),
      d.name || '',
      d.phone || '',
      d.email || '',
      d.clinic || '',
      d.service || '',
      d.date || '',
      d.message || ''
    ]);

    return ContentService
      .createTextOutput(JSON.stringify({ ok: true }))
      .setMimeType(ContentService.MimeType.JSON);
  } finally {
    lock.releaseLock();
  }
}

/**
 * Run this one, not doPost. Confirms the script is attached to the
 * spreadsheet, then writes a row the same way a real enquiry would.
 */
function testWrite() {
  var ss = SpreadsheetApp.getActiveSpreadsheet();
  if (!ss) {
    throw new Error('Not bound to a spreadsheet. Open the sheet and use Extensions, then Apps Script.');
  }
  Logger.log('Bound to: ' + ss.getName());

  doPost({ postData: { contents: JSON.stringify({
    receivedAt: new Date().toISOString(),
    name: 'Test row',
    phone: '0300 0000000',
    email: 'test@example.com',
    clinic: 'DHA Phase II',
    service: 'Dental consultation',
    date: '',
    message: 'Written from the Apps Script editor.'
  })}});

  Logger.log('Row appended. Check the sheet.');
}
```

The lock prevents two simultaneous submissions overwriting a row. The tab name
is not load bearing, so renaming the sheet will not break it. To publish: Deploy,
New deployment, type Web app, execute as Me, access Anyone, copy the /exec URL,
and set it as ENQUIRY_SHEET_URL in Vercel (all three environments), then
redeploy. "Anyone" only means the URL can be posted to without a Google login;
it cannot read the sheet or reach anything else. Do not run doPost by hand; run
testWrite, which also catches a standalone script that is not bound to the sheet.

If you would rather not use Google, the site posts a small JSON object
(receivedAt, name, phone, email, clinic, service, date, message) to whatever URL
ENQUIRY_SHEET_URL holds. Airtable, a Zapier or Make webhook, or a Notion database
will all accept it; only the URL changes.
